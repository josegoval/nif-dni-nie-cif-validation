The reference is generated from the JSDoc of the library's source each time the site is built, so it always matches the code. It has one page per entry point of the package, with every export: its signature, what each parameter and the return value mean, two examples that the library's tests run, the SPEC rule it follows, and the version that added it.

## Reading the reference

- **Options.** The validators take `IsValidOptions`, `validate()` takes `ValidateOptions`, and the schemas take the options of `validate()`. Each option's default and effect are listed on the main entry point's page.
- **Rules.** The links to rule IDs, such as `DNI-2`, open the [official sources](/nif-dni-nie-cif-validation/reference/official-sources/) page.
- **Aliases.** `isValidCif` and `isValidLegalEntityNif` are the same function, as are `isValidCifControlCode` and `isValidLegalEntityNifControlCode`, `CIF_REGEX` and `LEGAL_ENTITY_NIF_REGEX`, and `CIF_CONTROL_LETTERS` and `LEGAL_ENTITY_CONTROL_LETTERS`.
- **Deprecated.** `replaceNieLetter` is kept for version 1 code. It throws on bad input, unlike everything else.

The decisions behind the API are in [docs/api-design.md](https://github.com/josegoval/nif-dni-nie-cif-validation/blob/master/docs/api-design.md).
