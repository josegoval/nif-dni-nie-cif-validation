Cando un valor non é válido, `validate()` explica por que con catro campos de `error`:

- `code`: que clase de erro é, un de sete códigos, para que o seu código poida actuar segundo o caso;
- `rule`: o identificador da [regra de SPEC.md](/nif-dni-nie-cif-validation/gl/reference/official-sources/) que non se cumpre, como `DNI-2`;
- `message`: unha frase para a persoa usuaria, no idioma que indique;
- `expected`: só se o carácter de control é incorrecto, o correcto, para suxerir «quixo dicir…?».

```ts
import { validate } from "nif-dni-nie-cif-validation";

validate("12345678A").error;
// { code: "INVALID_CONTROL_CHARACTER", rule: "DNI-2", expected: "Z",
//   message: 'The control character is not correct: for this DNI it should be "Z".' }
```

`validate()` comproba o valor paso a paso e detense no primeiro fallo, así que sempre hai exactamente un erro. `type` e `normalized` están presentes en canto o formato é recoñecible, aínda que o carácter de control sexa incorrecto.

## Todos os códigos de erro

| `error.code` | Cando |
| --- | --- |
| `NOT_A_STRING` | O valor non é unha cadea de texto (`null`, un número, un obxecto). Nunca se converte nunha cadea |
| `EMPTY` | O valor está baleiro, ou só ten espazos e separadores |
| `INVALID_LENGTH` | O valor non ten o número de caracteres do seu tipo |
| `INVALID_FORMAT` | Un primeiro carácter incorrecto, letras onde van díxitos, un carácter de control da clase equivocada ou un prefixo `ES` sen `allowVatPrefix` |
| `INVALID_CONTROL_CHARACTER` | O formato é correcto, pero a letra ou o díxito de control non; `expected` contén o correcto |
| `UNSUPPORTED_TYPE` | Un documento válido dun tipo que `types` exclúe |
| `PLACEHOLDER` | Un número de exemplo (`00000000T`, `00000001R`, `99999999R`, `X0000000T`) con `rejectPlaceholders: true` |

Os dous últimos só se producen cunha opción: coas opcións predeterminadas, un documento válido sempre é válido.

## Todas as regras e as súas mensaxes

A táboa seguinte recolle, para cada código, todas as regras de SPEC que pode citar e a mensaxe que o acompaña, no idioma desta páxina. As mensaxes saen da propia biblioteca, así que son exactamente as que verán as súas persoas usuarias.

<ErrorCodesTable />

A regra distingue casos que comparten código. Por exemplo, `INVALID_CONTROL_CHARACTER` cita `DNI-3` cando a letra é unha das que nunca aparecen (I, Ñ, O, U), `CIF-3` cando o control dun CIF é unha letra e a clave leva un díxito (ou ao revés) e `CIF-4` cando é da clase correcta pero ten un valor incorrecto:

```ts
import { validate } from "nif-dni-nie-cif-validation";

validate("12345678I").error?.rule; // "DNI-3"
validate("B1234567A").error?.rule; // "CIF-3": a B leva díxito
validate("B12345675").error?.rule; // "CIF-4": un díxito, pero non o correcto
validate("T1234567A").error?.rule; // "NIF-1": ningún NIF comeza por T
validate("X11234567L").error?.rule; // "NIE-3": 10 caracteres, pero non é a forma antiga do NIE
```

## Escoller o idioma

O inglés vén incluído. Cada un dos demais idiomas é un punto de entrada á parte, así que un bundle só contén os idiomas que importa. Importe o obxecto do idioma e páseo como `locale`:

| Idioma | Importación |
| --- | --- |
| Inglés (predeterminado) | `import { en } from "nif-dni-nie-cif-validation/locales/en"` |
| Castelán (español) | `import { es } from "nif-dni-nie-cif-validation/locales/es"` |
| Catalán (català), tamén para o valenciano | `import { ca } from "nif-dni-nie-cif-validation/locales/ca"` |
| Éuscaro (euskara) | `import { eu } from "nif-dni-nie-cif-validation/locales/eu"` |
| Galego | `import { gl } from "nif-dni-nie-cif-validation/locales/gl"` |

```ts
import { describeCifOrganisation, validate } from "nif-dni-nie-cif-validation";
import { eu } from "nif-dni-nie-cif-validation/locales/eu";

validate("12345678A", { locale: eu }).error?.message;
// "Kontrol-karakterea ez da zuzena: NAN honetan «Z» izan beharko luke."
describeCifOrganisation("B", eu); // "Erantzukizun mugatuko sozietatea"
```

A mesma opción `locale` funciona en `validate()`, en `describeCifOrganisation()` e en todos os esquemas (`zNif({ locale })`, `vNif({ locale })`, `yNif({ locale })`). Tamén traduce `meta.orgDescription`, o tipo de entidade dun CIF.

Para seguir o idioma da persoa usuaria, asigne un obxecto de idioma a cada etiqueta de idioma, cun predeterminado:

```ts
import { type NifLocale, validate } from "nif-dni-nie-cif-validation";
import { ca } from "nif-dni-nie-cif-validation/locales/ca";
import { en } from "nif-dni-nie-cif-validation/locales/en";
import { es } from "nif-dni-nie-cif-validation/locales/es";

const LOCALES: Record<string, NifLocale> = { ca, en, es };
const localeFor = (language: string) => LOCALES[language.slice(0, 2)] ?? en;
const locale = localeFor("ca-ES"); // por exemplo, navigator.language

validate("12345678A", { locale }).error?.message;
// "El caràcter de control no és correcte: per a aquest DNI hauria de ser «Z»."
validate("B12345674", { locale }).meta?.orgDescription; // "Societat de responsabilitat limitada"
```

O catalán serve tamén para o valenciano: a AEAT dá os mesmos nomes de entidade en ambos, e as mensaxes non usan ningunha forma que difira entre os dous estándares.

<Aside type="caution" title="Pase o obxecto, non o seu código">
`{ locale: "es" }` é un erro de TypeScript e, en tempo de execución, unha cadea ignórase: as mensaxes seguen en inglés. Non se lanza ningunha excepción, así que o formulario segue a funcionar, pero no idioma equivocado. Importe o obxecto.
</Aside>

## As súas propias mensaxes

`code` e `rule` son estables, así que pode asocialos aos seus propios textos e usar a mensaxe da biblioteca como alternativa:

```ts
import { type NifErrorCode, validate } from "nif-dni-nie-cif-validation";

const MESSAGES: Partial<Record<NifErrorCode, string>> = {
  EMPTY: "Please enter your tax ID.",
  UNSUPPORTED_TYPE: "Please enter a personal tax ID, not a company's.",
};

const error = validate("B12345674", { types: ["DNI", "NIE"] }).error;
error && (MESSAGES[error.code] ?? error.message); // "Please enter a personal tax ID, not a company's."
```

Un idioma é un obxecto normal (`NifLocale`), así que tamén pode escribir un para outro idioma. Se a un obxecto de idioma lle falta un texto, úsase o inglés para ese texto. A terminoloxía e as fontes de cada nome de entidade traducido están en [docs/translations.md](https://github.com/josegoval/nif-dni-nie-cif-validation/blob/master/docs/translations.md) (en inglés).

## Nos esquemas

Os esquemas de Zod, Valibot e Yup dan a mesma mensaxe, e poñen o código e a regra onde cada biblioteca o permite:

| Biblioteca | Mensaxe | Código e regra |
| --- | --- | --- |
| Zod | a `message` do issue | os `params` do issue: `{ code, rule, expected? }` |
| Valibot | a `message` do issue | o propio issue: `issue.code`, `issue.rule`, `issue.expected` |
| Yup | a `message` do `ValidationError` | os `params` do erro: `{ code, rule, expected? }` |

Consulte [Validar formularios](/nif-dni-nie-cif-validation/gl/guides/validating-forms/) para ver exemplos.
